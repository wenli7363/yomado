# yomado · 夜窗 — Windows 开发版

目标平台：Windows 11 x64。应用使用 .NET 10 / WPF，显示驱动使用
C++ / UMDF 2.25 / IddCx 1.4。第一版复刻原版的虚拟屏与窗口管理能力。
界面采用 Windows 视觉风格，跟随系统明暗主题，并兼容高对比度模式。

## 功能

- 创建多块独立命名的虚拟屏；提供 1920×1080、2560×1440 和 2 倍像素模式。
- 按实际排列展示屏幕，按来源屏分组展示可见普通窗口的应用图标。
- 拖动图标只移动来源屏上的该应用窗口；右键也可移入其他虚拟屏或返回。
- 从资源管理器拖入已运行应用的 exe / 快捷方式，明确选择该应用的全部普通窗口。
- 跨虚拟屏转移保留最初的实体屏位置；返回原屏恢复，返回其他实体屏居中。
- 在不同 DPI 的屏幕之间换算窗口尺寸；原显示器不可用时回退到可用实体屏。
- 关闭虚拟屏前恢复并验证窗口；失败时保留屏幕、记录和重试入口。
- 关闭面板后保留系统托盘；通过托盘退出时先恢复所有工作屏窗口。
- 屏幕配置保存到 `%LOCALAPPDATA%\Yomado\screens.json`；重启不自动创建虚拟屏。
- 已保存且未启动的屏幕直接显示在面板下方，可以启动、编辑；“新建屏幕”填写配置后直接创建并启动。
- 创建及移入前检查扩展模式与实体主屏，核对原屏的排列、DPI、旋转、刷新率和模式。
  检测到复制显示或并发配置变化时停止操作；不会用旧快照覆盖新的显示设置。
- 关闭屏幕或退出时，先恢复普通窗口；仍有不可移动对话框时按应用列出并请求确认，默认取消。
  确认只适用于当前屏幕及这批窗口，新弹窗或窗口身份变化需要重新确认。
- 普通窗口位置只在本次运行期间保存；微信额外保存带窗口身份标记的几何检查点。
  微信需要先返回实体屏，再移入其他虚拟屏。恢复不能代替登录。
- 手动检查 Windows 发布版本；无自动安装、遥测、设备标识上报。
- 运行虚拟屏时请求系统及显示桌面保持唤醒。
- 普通鼠标停留在实体屏边缘，不会直接滑入 Yomado 虚拟屏；保留既有屏幕间的移动。
  边界按完整物理像素计算；程序注入的移动同样受约束，仅明确授予的键鼠借用临时放行。
- 支持共用键鼠的限时借用申请；用户明确允许后，实体主屏持续显示倒计时和“停止”。

虚拟屏共享当前会话的鼠标、键盘和焦点。截图与输入由已有 Agent 工具提供。
仅有虚拟屏不代表可以一边开发、一边让 Agent 独立操作。

## Agent 共用键鼠借用

先运行应用，再通过命令行申请；请求与回应使用当前用户、当前桌面会话的命名管道。
以下 PowerShell 管道会等待命令结束并输出 JSON：

```powershell
& .\Yomado.exe --input request --agent Codex --reason '操作本次任务的窗口' --seconds 120 | Out-String
& .\Yomado.exe --input status --lease '<上一步返回的 leaseID>' | Out-String
& .\Yomado.exe --input release --lease '<同一个 leaseID>' | Out-String
```

请求等待最多 60 秒，无回应自动拒绝。租期默认 120 秒，限制在 10–600 秒。
Agent 只有收到 `granted` 才能使用共用键鼠，操作前检查同一租约仍为 `active`，
完成后归还。用户点击“停止”、到期或应用退出都会结束租约；状态查询使用单调时钟
核对截止时间，系统时间变化不会延长许可。正常归还或到期时，尽力恢复原前台窗口及
仍位于实体屏上的原光标位置，已关闭或身份变化的窗口不会被激活。

该流程是现有输入工具的权限协调，不注入输入，也不在系统层拦截其他工具。
Yomado 为既有实体屏及其他厂商屏幕设置完整像素范围的系统光标边界（`ClipCursor`），
在 Windows 处理跨屏移动前阻止光标进入 Yomado 虚拟屏，不使用任务栏工作区或虚拟屏高度。
仅在一个矩形可包含这些屏幕且不覆盖 Yomado 屏幕时启用；复杂排列保留事件及位置复核。
不会扩大其他应用设置的较小光标范围。键鼠借用获准前先解除自己设置的限制，结束或到期后恢复。
退出时只恢复仍与本应用写入一致的范围；其他应用已更改范围时保留其设置。
屏幕和键鼠仍属于同一桌面会话。返回 `busy`、`denied`、`timeout`、`ended`、
`unknown` 或 `not-running` 时，Agent 应停止输入并重新与用户协调。

## 上游同步范围

2026-10-27 已同步 macOS 上游至 `c1b446f`（包含 v0.3.7 后的主线更新），
Windows 已接入保存屏幕操作、关闭确认、拓扑保护及键鼠借用。
Dock、Stage Manager 和 Sparkle 为 macOS 专用；Windows 保留手动检查自身发布包的
更新方式，尚未提供自动下载安装及升级后工作区恢复。

HiDPI 在本版表示 2 倍物理像素。Windows 的每屏缩放仍由系统管理，不能把
创建 3840×2160 自动等同于已经获得 1920×1080 的逻辑桌面。

## 构建

需要 Visual Studio 2022 C++ 工具、Windows SDK 10.0.26100.0，以及 .NET 10 SDK。
项目内可以恢复 .NET / WDK 构建依赖，不安装驱动或修改系统信任设置：

```powershell
.\windows\bootstrap.ps1
.\windows\build.ps1 -Publish
.\windows\test.ps1
.\windows\package.ps1
```

应用：`windows/artifacts/app/Yomado.exe`。
驱动：`windows/artifacts/driver/`。
开发包：`windows/artifacts/Yomado-Windows-0.1.0-dev-x64.zip`。
这些是本地生成物，未提交到仓库，也未公开发布。

仅构建应用可用 `build.ps1 -ApplicationOnly`；无桌面会话的环境只运行
`test.ps1 -CoreOnly`。C++ EDID 策略测试用 `test.ps1 -NativePolicyTests`，
需要主机策略允许启动新编译的测试 EXE。

驱动安装并确认启动后，可显式执行 `test.ps1 -VirtualDisplayTests`。
它会临时创建两块虚拟屏、依次验证四种分辨率，仅移动自己的不可见子进程
测试窗口，验证跨屏、原点恢复及最小化恢复，最后移除测试屏。
运行前从托盘退出 Yomado；该选项不修改保存的屏幕配置。

## 驱动签名与安装

构建和打包生成的驱动目录是**未签名开发产物**，不是可直接部署的正式驱动。
本机应用控制策略也可能拒绝未签名的应用或安装辅助 EXE。

`prepare-signing.ps1` 可以生成供检查的本地测试签名开发包。它在
`CurrentUser\My` 创建短期、仅用于代码签名的身份，导出公钥证书和指纹，
不将证书加入受信任根或发布者。包中的 `SIGNING-INFO.json` 说明签名身份。
此证书不能代替正式发布者签名或微软驱动签名流程。

仅在机器所有者明确批准该指纹后，才可运行包内的
`trust-development-certificate.ps1 -ApprovedThumbprint ...`。它要求管理员权限，
和明确批准的指纹，写入本机 Root / TrustedPublisher；应用控制策略可能仍需另行允许
该发布者。不要以更换签名为由关闭安全策略。

发布前需要验证代码签名与驱动包签名路线，完成适用的 Windows 驱动提交、
兼容性测试和安装验收。开发测试证书的信任安装必须由机器所有者明确批准；
本项目的构建、测试、打包脚本不会添加信任证书或降低系统安全策略。

使用完整发布包打开 Yomado，点击“一键安装驱动”，允许 Windows 管理员权限提示。
应用会自动检测设备状态，并通过驱动协议确认就绪；就绪后同一个按钮置灰，
状态文字显示检测结果。异常时可通过同一个按钮重新安装，操作前请关闭所有 Yomado 虚拟屏。
安装前验证包内签名；本地开发版首次安装会明确请求信任指定测试证书。
安装不会自动创建虚拟屏或重启电脑。

手动维护仍可使用发布目录中的 `install-driver.ps1`，需先从托盘退出 Yomado，
然后在管理员 PowerShell 中运行；`-Remove` 只移除 Yomado 自己的根设备。

## 验证范围

核心测试覆盖来源屏隔离、跨虚拟屏原点保留、失败恢复、显示器缺失、
窗口句柄复用、不同 DPI、设置损坏和 Windows 更新筛选，另覆盖关闭确认范围、
镜像/拓扑变化、键鼠借用的并发及截止时间边界。

本次上游同步通过 84 项核心测试、应用编译、原生测试窗口恢复、托盘检查、
只读命名管道 IPC 检查和明暗预览；未重新执行真实虚拟屏、对话框关闭或键鼠借用
允许/停止的现场验收。历史真实驱动验证结果不代表本次新功能已通过这些现场检查。

`test.ps1` 的原生窗口测试只移动并恢复一个专用的不可见子进程窗口，
不创建显示器，不移动用户应用，不执行键鼠输入。明暗预览使用示例数据。
这些检查不能证明 QDoc、浏览器或真实虚拟屏的截图/输入已通过。
鼠标边界的策略测试覆盖 4K / 225% 实体屏与 1080p 虚拟屏、完整屏幕高度、负坐标及
多屏移动。系统光标边界方案通过 123 项核心测试、应用编译及空快照下的原生注册和退出检查。
2026-10-27 用户在本机确认右边缘穿透和截图半屏现象已解决；运行的系统边界版只读诊断显示
`ClipApplied=true`，实际限制范围为实体屏完整的 3840×2160，未启用键鼠借用。
此结果不代替 Agent 在虚拟屏上的截图/输入、复杂多实体屏排列及睡眠唤醒等兼容性验收。

本机已完成真实驱动验收：1920×1080、2560×1440、3840×2160、5120×2880
创建及关闭通过；双虚拟屏转移、225% / 100% DPI 换算和最小化返回通过。
验证后实体主屏位置、分辨率、缩放与前台焦点保持一致，测试屏全部回收。
这是当前主机的开发验证，真实应用截图/输入及下列兼容性验收仍需完成。

驱动安装后仍须现场验证：

1. 创建和关闭单屏、多屏，确认实体主屏及既有排列保持不变。
2. QDoc 等真实应用移入、跨屏、返回，检查普通、最大化和最小化窗口。
3. 用现有 Agent 工具选择该屏，验证新截图及一次可逆输入。
4. 不同 DPI、睡眠唤醒、显卡重置、应用异常退出后的恢复。
5. 微信检查点重启恢复、可识别模态框触发，以及不同微信版本兼容性。

微信的自动恢复仅识别有限的 Win32 模态/登录窗口类；不会读取聊天内容，
也不能保证识别每个版本的自定义安全界面。保留人工返回入口。

## 开发诊断

```powershell
Yomado.exe --diagnose diagnostics.json
Yomado.exe --input pointer-status
Yomado.exe --preview-ui preview.png light
Yomado.exe --preview-ui preview-dark.png dark
Yomado.exe --test-input-lease input-lease-smoke.json
Yomado.exe --virtual-display-test virtual-display-test.json
```

诊断默认散列显示器标识，只记录几何、缩放与窗口数量，不记录窗口标题或内容。
`--input pointer-status` 只读取正在运行实例的边界状态和鼠标事件计数，不申请键鼠借用或激活窗口。
`--include-device-identifiers` 仅供本地排障，分享前清理标识。

应用使用 MIT；`driver` 目录的微软示例衍生代码使用 MS-PL。
详见 `THIRD-PARTY-NOTICES.md`。
